## 10. Inventory and checkout correctness

Implement meaningful backend safeguards.

Required behavior:

- Prevent overselling during concurrent checkout.
- Reserve inventory for a bounded period.
- Release expired or failed reservations.
- Convert reservations into completed stock deductions exactly once.
- Use database locking or atomic conditional updates appropriately.
- Make checkout idempotent.
- Persist payment event identifiers to prevent duplicate processing.
- Record inventory changes in an auditable ledger.

Define and implement a documented checkout state machine.

Handle the important race cases:

- Two customers attempt to buy the last unit.
- A customer submits checkout twice.
- A payment callback arrives twice.
- Payment fails after stock reservation.
- A reservation expires.
- A late successful payment arrives after expiration.
- A cancellation races with fulfillment.

For late payments, choose a safe documented policy, such as reacquiring stock if available or entering a refund-required state.

Do not use Redis as the authoritative inventory database.
